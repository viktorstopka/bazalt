# Bazalt — Reconciliation: design docs vs. code

Compares `VALUE_MODEL.md`, `SIGNAL_TYPES.md`, `DOMAINS.md` (status: design draft) against the
engine/plugin/UI as they actually stand — the working tree, including the uncommitted changes
already sitting there (`ValueTypes.h`, the `hasFallbackWhenUnconnected` NaN-sentinel pattern in
`GraphCompiler.cpp`, `DelayNode`'s port/parameter split), not just the last commit.

The three docs were written without seeing the code. Where they clash with what the code actually
does, or with a decision `ARCHITECTURE.md`/`NODE_EDITOR.md` already made deliberately, this file
says so plainly rather than picking a winner silently. Recommendations are proposals for you to
approve, reject, or amend — nothing here has been implemented.

**How to read the tables:** *Cost* is the honest blast radius, not a sandbagged estimate. *Breaks
patches?* — as of today nothing persists a real user-built graph (M10's editor is disconnected from
the engine; only the hardcoded proof graphs and the 32-slot macro pool exist as real state), so
"breaks patches" mostly means "breaks the factory/proof graphs and any patch-format assumption,"
not "breaks a library of real user content" — that changes once M10 gets wired to the engine, which
is exactly why several items below say *before* first catalogue ships.

---

## 0. Cross-cutting: this collides with already-planned M11–M13, not just with code

`docs/MILESTONES.md` already plans M11 (live visualization), M12 (node-type-specific interaction
polish), M13 (assist menu/shell polish). This isn't idle — M12 specifically commits to:

- "Macro node + Constraints popover (Type/Shape/Enum, NODE_EDITOR.md conflict-log item #10's
  host-automation-warning behaviour)"
- "Growable ports (Mix/Math-style, capped, never below 2)"

Both are the *same features* `VALUE_MODEL.md` §6 and `SIGNAL_TYPES.md` §6 specify at the
foundational schema level — but M12 currently scopes them as **UI-only, disconnected from the
engine** (per CLAUDE.md's own M10 note: `graphStore.ts` never calls the real command bridge).
Building M12 as currently written risks building the UI-mock version of Macro/growable-ports twice:
once now, disconnected, and again once the real `PortGroup` schema and Macro-node engine support
exist.

There's also a direct, **pre-existing, reasoned rejection** of `VALUE_MODEL.md` §6's whole
direction already on record: `NODE_EDITOR.md`'s own conflict log (item #10) considered "make Macro
a real wireable node" and chose instead "keep the host-facing parameter a plain 0–1 float
unconditionally; Type/Shape/Enum are UI-side interpretation only" — specifically to protect
ADR-0004's cross-host VST3 `restartComponent` guarantee. See §1.2 below; this is the single biggest
point of friction in the whole reconciliation.

**Recommendation:** don't silently renumber M11–M13. Treat this reconciliation's own milestones
(proposed starting at M14, per your instruction) as landing *before* M12 does its
Macro/growable-ports work for real, and narrow M12's scope at that point to "wire the UI to the now-
real engine schema" rather than "build a second local mock." That's a milestone-plan edit, not a
code conflict — flagged here so it isn't lost, actioned in `MILESTONES.md` itself (§4 below).
